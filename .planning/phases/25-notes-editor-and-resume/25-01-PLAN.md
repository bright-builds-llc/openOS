| Boundary | Description |
|----------|-------------|
| localStorage -> Notes content parser | Durable note content is untrusted JSON and must parse into typed `NoteContentDocument` before use. |
| localStorage -> Notes session parser | Disposable resume snapshots are untrusted JSON and must parse through `appSessionStorage.ts` plus Notes-specific schema validation. |
| Notes helper -> durable storage writer | Structured user-authored content crosses into the durable `openos.apps.notes.notes` key. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-01-01 | Tampering | `notesSession.ts` | mitigate | Strictly parse version 1 session payloads and delegate malformed JSON, unsupported versions, invalid payloads, and reset failures to `readAppSessionSnapshot`; cover invalid shapes in `notesSession.test.ts`. |
| T-25-01-02 | Tampering | `notesStorage.ts` | mitigate | Structured durable write helpers must call only the durable Notes key path through `writeSnapshot`; acceptance grep blocks session helper imports and broad clear calls. |
| T-25-01-03 | Denial of service | `writeNotesSession` | mitigate | Return `AppSessionWriteResult` from `writeAppSessionSnapshot` so UI can truthfully report session write failure without blocking durable note edits. |
| T-25-01-04 | Elevation of privilege | `notesContent.ts` | mitigate | Keep note text as plain strings in typed blocks and do not introduce HTML parsing/rendering helpers or `dangerouslySetInnerHTML`. |
| T-25-01-05 | Information disclosure | local-only durable Notes data | accept | Phase 25 remains local-only browser storage with no network, account, sync, or secret-handling boundary; existing local-only warning remains the user-facing disclosure. |
</threat_model>
