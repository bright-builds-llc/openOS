## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline gaps inside checklist rows and compact metadata |
| sm | 8px | Field label gaps, block control gaps, checkbox-to-text spacing |
| md | 16px | Default padding for editor blocks, inputs, notices, and panel content |
| lg | 24px | Section spacing between toolbar, folder strip, list, and editor |
| xl | 32px | Large vertical separation inside the Notes app surface |
| 2xl | 48px | Major app-level breaks when viewport height allows |
| 3xl | 64px | Reserved for page-level spacing outside the compact Notes editor |

Exceptions: preserve existing Notes chrome values already in `notes.css` when untouched by this phase; new structured-editor controls must use the declared scale. Minimum touch target for editor actions, block remove buttons, checklist checkboxes, and toolbar buttons is 44px. Pill radii may keep `999px`; panel and input radii should reuse the existing 18px/20px/24px Notes values without adding new arbitrary radii.

## Interaction Contract

Phase 25 extends the current Notes screen, not the app shell. Preserve the existing order: hero, local-only warning, search/folder toolbar, folder filter strip, note list, editor panel. On narrow iPhone portrait layouts, the list and editor remain stacked with no horizontal overflow; at wider widths the current two-column list/editor layout may remain.

The editor surface renders the Phase 24 typed blocks directly: `paragraph`, `heading`, and `checklistItem`. New notes start as structured documents. Existing paragraph-only notes open in the structured editor without a migration prompt.

Required block controls:

| Control | Behavior |
|---------|----------|
| `Add Text` | Appends a paragraph block and focuses its multiline text field |
| `Add Heading` | Appends a heading block and focuses its single-line text field |
| `Add Checklist Item` | Appends an unchecked checklist item and focuses its text field |
| Checklist checkbox | Toggles only that checklist item's `checked` state |
| `Remove Block` | Removes only that block; no confirmation required for individual blocks |

Block fields are controlled React inputs. Edits save synchronously to durable Notes content and keep search/previews using structured text. Checked checklist text may use reduced opacity or line-through, but the text must stay readable and searchable.

Resume behavior must restore the last meaningful selected folder, note, search text when non-empty, and selected/focused block after home navigation or reload. If a saved folder, note, or block no longer exists, select the nearest valid folder/note/block or show the existing empty state. Malformed session snapshots reset through `appSessionStorage.ts`; durable notes and folders must remain untouched.

Use these stable test IDs for new browser coverage: `notes-add-text`, `notes-add-heading`, `notes-add-checklist-item`, `notes-block-input:{index}`, `notes-block-check:{index}`, `notes-block-remove:{index}`, and `notes-session-warning`.
