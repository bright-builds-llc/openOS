<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User-authored text -> React controls | Title and block text enter controlled form fields and must not become raw HTML. |
| React editor -> durable Notes storage | User edits cross from component state into `openos.apps.notes.notes`. |
| React session effects -> session storage | Disposable UI hints cross into `openos.apps.notes.session` and may fail independently from durable edits. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-02-01 | Elevation of privilege | `NotesEditor.tsx` | mitigate | Render user text only through controlled `value` props and acceptance grep for `dangerouslySetInnerHTML` and `innerHTML`. |
| T-25-02-02 | Tampering | `NotesApp.tsx` session restore | mitigate | Initialize and re-resolve session through `resolveNotesSession` so stale folder, note, and block references cannot point at missing durable data. |
| T-25-02-03 | Denial of service | `NotesApp.tsx` session writes | mitigate | Render `notes-session-warning` when `writeNotesSession` reports unavailable while durable edits continue through `updateStoredNoteContent`. |
| T-25-02-04 | Tampering | Delete note flow | mitigate | Require the exact destructive confirmation copy before `deleteStoredNote` to reduce accidental durable Notes deletion. |
| T-25-02-05 | Information disclosure | visible warning copy | accept | Local-only unencrypted browser storage remains established project behavior; preserve the existing local-only warning and do not add sync/account claims. |
</threat_model>
